# Web application

| Folder | Responsibility |
| --- | --- |
| `src/client/` | React components, the browser entry `client.tsx` and the stylesheets. |
| `src/server/` | The Hono routes, inspection worker, admission, SQLite storage, report publication and `src/server/fixtures/`. |
| `src/publishedReport.ts` | The published report types and text transforms that both sides import. |
| `public/assets/` | The icon, fonts and font licenses. |

The file names below sit in `src/client/` or `src/server/`. `vite.config.ts` and the Dockerfile stay at the workspace root.

The `@health-code/web` workspace serves the inspection site. Bun runs its Hono entry in `server.ts`. It serves the Vite client, the anonymous submission API, resumable event streams and server-rendered Inspection Reports. The browser hydrates `Page.tsx`. `Timeline.test.ts` covers live and saved event rendering. `Timeline.tsx` renders ordered Inspection Events and pinned Sandbox Events. `ReportView.tsx` renders source locations, replacement evidence, adoption outcomes, recorded model usage and the tested Patch handoff. “What the health inspector could verify” lists the upgrade install, typecheck and tests separately. Older saved reports can omit optional details.

`executeInspection.ts` owns startup recovery and the bounded worker. `admitInspections.ts` admits hosted submissions against the live limits and joins existing inspections. `storeInspections.ts` owns the SQLite schema and transactions. `stopInspections.ts` stops queued or running inspections. Anyone can stop a local inspection. On the hosted site only the starting visitor can stop an inspection nobody joined. `StopInspection.tsx` stops in one click. A stopped upgrade test returns to its upgrade menu. `streamInspection.ts` replays committed events in pages after the caller’s cursor. Timeline entries fetch raw output on disclosure through the license-checked detail route. Each patch has its own download and copy instructions. `PatchPreview.tsx` loads a patch into a modal with its download. `PatchText.tsx` highlights it by file type, and `splitPatch.ts` folds any file past the display limit to one line. Within each dependency target, the report numbers the upgrade and optional feature patch when a prerequisite is recorded. Feature patch instructions include the prerequisite digest and URL. `publishReport.ts` constructs the public report and verifies every digest before publication. The original library report remains on the server. `verifyRepository.ts` checks GitHub visibility and license detection at the inspected commit. `executeInspection.ts` records the license at the inspected commit before the run so live output can show. An unverified license is looked up again before publication.

`InspectionDetails.tsx` renders the table below the inspection log with Baseline checks. `logInspection.ts` records terminal state and bounded cost evidence.

`recordAdmissions.ts` owns quota reservations, UTC accounting and sharing cohorts. Its `countRemainingInspections` count enforces the daily allowance and supplies the hosted header’s “demo calls left today” label. `launchLimits.ts` refreshes the limits snapshot. `verifyVisitor.ts` authenticates the operator and verifies visitor identity and Turnstile before a paid start. The limits, identity and storage checks run through the same submission path.

Use the public `health-code` package for live Inspections. In development, `replayInspection.ts` streams the version 2 Inspection Report and event intervals from `src/server/fixtures/recorded/`. Tests also read the original version 1 recording. Production rejects replay configuration.

From the root, build the library with `bun run --cwd packages/health-code build`. Run `doppler run --project health-code --config dev -- bun run --cwd apps/web dev` for live inspections at `http://localhost:3000`. Use `bun run --cwd apps/web replay` for the credential-free recording. Both support `PORT`. `createLocalSiteRuntime.ts` uses separate local SQLite queues and a local sandbox namespace. Developers fund live work with their own Runta and model credentials. Local workers use the inspection queue directly. The production entry always uses hosted admission. `developSite.ts` serves Vite Fast Refresh and reloads the Hono routes. `startInspections.ts` initializes the hosted worker and its admission limits. Browser and stylesheet edits preserve the worker. Run `bun test apps/web` for HTTP, persistence, replay and publication tests. Build the browser assets with `bun run --cwd apps/web build` and serve them with `bun run --cwd apps/web start`.

See `HOSTING.md` for the Northflank deployment, limits, health checks and backups.

Follow code-style, jsx-conventions and vercel-react-best-practices. Review browser interactions against web-design-guidelines.

The hosted library caller keeps its local model handles. The timeline pins the Model Request Sandbox startup Sandbox Event. The saved event includes the runtime ID.

The home form requests registry discovery through **New features**. The menu defaults to descending declaring workspace count. `style.css` spaces sections, blocks and inline items with `--section-gap`, `--block-gap` and `--inline-gap`. `--block-gap` separates a button from its neighbors on either side, and `.button-row` lays out text beside a button. Headings use Space Grotesk, body text uses IBM Plex Sans and code uses JetBrains Mono. Vite copies the supplied icon, fonts and font licenses from `public/assets/` into the production assets directory. `UpgradeMenu.tsx` groups target versions by dependency, supports three sorts, search and the **Patch available** filter, which appears once the menu has a tested patch. `upgradeMenu.css` styles these controls and the pagers. `fonts.css` loads the typefaces and `promptBox.css` styles the prompt and its highlighted tokens. Each dependency page loads upstream release features for its visible versions. Discovery and browsing use no model. `createLiveSource.ts` reads the same model settings as the MCP and chooses no model. Selecting a target queues only that upgrade at the discovered commit. Fresh discovery uses a normal hosted admission. Complete upgrade menus can be reused for one hour.

`inspectionSource.ts` defines the hosted and replay source contract. `cacheReleaseFeatures.ts` shares public release lookups across visitors. Upgrade menu pages send the visible choices and fetch five features per version at a time. `UpgradeView.tsx` renders one upgrade and `ReportControls.tsx` owns the shared link and copy controls.

`buildReportInvestigationPrompt.ts` selects report evidence for the downstream coding agent. `ReportActions.tsx` shows the selected patch prompt or an investigation prompt for incomplete checks in the scrollable `PromptBox.tsx`, which highlights tokens with `prism-react-renderer`. The page header links to Runta signup, MCP setup and the GitHub README. Its Copy report link copies the canonical report URL.

The hosted repository sandbox has 8 GiB of physical memory. Tools such as oxlint can reserve larger virtual address ranges and consume RAM as they use the pages.

To apply a tested Patch from a licensed Inspection Report, copy the prompt under **Upgrade prompt for your coding agent** and paste it into Claude Code or Codex from the repository checkout. The instructions include the download URL, SHA-256 digest and tested commit. A Feature Patch also identifies its required Upgrade Patch. When there is no patch, the report says why. If checks did not finish, **Troubleshooting prompt for your coding agent** gives your agent the inspected revision, available check results and a link to the Inspection Report.
