# Sandbox guest tools

`project.ts` is the entry for dependency discovery, Baseline and Upgrade commands. `detectProject.ts` reads lockfiles and environment variable names and bumps a dependency. `readProjectFiles.ts` reads bounded project files and workspace manifests. `removeOutdatedLockfileEntries.ts` removes npm lockfile entries whose version differs from an exact manifest version before npm resolves a change. `fetchRegistryVersions.ts` looks up at most 16 packages concurrently with an eight-second timeout and a 16 MiB response limit per request. `readReleaseAge.ts` reads the repository’s minimum release age from the package manager. When one applies, the lookup requests publish dates for at most four packages at once, with a 20-second timeout and a 48 MiB limit, and offers only releases old enough to install. The guest reserves time to return completed lookups before the host deadline. Deprecated releases are never offered. `selectRegistryVersions.ts` selects stable registry versions, including older releases for repositories with a minimum release age. `readTestReport.ts` translates JUnit and JSON test results into comparable identities. `nodeTestReporter.ts` is a separate bundle that Node's test runner loads to write JSON results.

`observe.ts` is the entry for the observer bundle. `readSystemCallLogLines.ts` streams the protected syscall capture in one pass with a 512 MiB disk limit. `inspectSandboxActivity.ts` interprets the protected network and filesystem evidence after an Install Check. `trackWorkingDirectories.ts` follows each traced process’s working directory. `trackFileLinks.ts` follows recorded in-project symlink targets for metadata changes. Unknown targets and ambiguous changes to writable mappings leave filesystem coverage incomplete. The library build bundles the project, observer, agent and patch tools for Node. Verify them using the recorded projects and the shared live provider contract.

`agent.ts` performs one isolated inference request. `managePatch.ts` owns the protected Git index, checks that repository commands preserved the tracked candidate tree, and replays each mailbox in a fresh checkout. `readUsage.ts` measures installed bytes and identifies dependency call sites. `measureTests.ts`, `collectTestInventory.ts` and `readPatchVerificationInputs.ts` reconcile test evidence and report the inventory in bounded pages. The supervisor stores the completed inventory outside the project. Repository commands can write only the raw reporter output for their own test invocation.

`protectTestSupport.ts` follows the inspected runner configuration, explicit command flags and test imports. `createTestAliasResolver.ts` resolves aliases from inherited local configuration. `readViteAliases.ts` reads statically readable aliases, `resolve` settings and plugins from a Vite configuration. `../src/patches/readSyntax.ts` parses source for these modules and the test-edit review. Source edits must preserve test-only helpers, setup modules and their dependencies. An unresolved runner configuration prevents source edits. Test captures use a 16 MiB reporter filesystem and immutable pages of 100 cases. Repository paths, lifecycle hooks and test file metadata use a separate byte-bounded cursor.

The Model Request Sandbox has no project checkout or guest bundles. The provider invokes the base image’s HTTPS client with a fixed executable and structured stdin. Editing tools belong only to Agent Attempts.
