# Sandbox guest tools

`project.ts` is the entry for dependency discovery, Baseline and Upgrade commands. `inventory.ts` reads lockfiles, workspace manifests, and environment variable names. `selectRegistryVersions.ts` selects stable registry versions, including older candidates for repositories with a minimum release age. `readTestReport.ts` translates JUnit and JSON test results into comparable identities.

`observe.ts` interprets the protected network and filesystem evidence after an Install Check. `trackFileLinks.ts` follows recorded in-project symlink targets for metadata changes. Unknown targets and ambiguous changes to writable mappings leave filesystem coverage incomplete. The library build bundles the project, observer, agent and patch tools for Node. Verify them using the recorded projects and the shared live provider contract.

`agent.ts` performs one isolated inference request. `managePatch.ts` owns the protected Git index, checks that repository commands preserved the tracked candidate tree, and replays each mailbox in a fresh checkout. `readUsage.ts` measures installed bytes and identifies dependency call sites. `measureTests.ts`, `collectTestInventory.ts` and `readIntegrity.ts` reconcile test evidence and report the inventory in bounded pages. The supervisor stores the completed inventory outside the project. Repository commands can write only the raw reporter output for their own test invocation.

`protectTestSupport.ts` follows the pinned runner configuration, explicit command flags and test imports. `readTestAliases.ts` resolves aliases from inherited local configuration. Source edits must preserve test-only helpers, setup modules and their dependencies. An unresolved runner configuration prevents source edits. Test captures use a 16 MiB reporter filesystem and immutable pages of 100 cases.
